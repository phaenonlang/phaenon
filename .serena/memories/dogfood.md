# Dogfood — the Tequila targets

Every milestone has a Tequila target, and a milestone is not done until the target's own test
suite passes on compiled output (`../design/roadmap.md` §3). The end goal behind it: tequila.dev —
about 50 repositories on Symfony, ext-mongodb, NATS and amp — running on Phaenon. That is why
ecosystem compatibility constrains every design choice.

Tequila repos have their own rules (`~/labs/tequila/platform/CLAUDE.md`): Conventional Commits,
squash-merged PRs, release-please. Do not apply Phaenon's commit style there, and do not merge or
push dogfood work without a maintainer's go-ahead.

## `tequila/reflection` — M1, M2

- Repo `~/labs/tequila/reflector` (package name differs from the directory).
- Branch **`phaenon-dogfood`**, one commit `b4c7753` *Compile the library from Phaenon (.phn)
  sources* on top of `main` at `c29d256`. **Local only — never pushed.** `main` is the library's
  release line; check `git branch --show-current` before working there.
- 18 `.phn` files (4 in `src/`, 14 in `tests/`) with the generated `.php` committed beside them.
  2026-10-29: `class-string<T>` → `class<T>` in the sources (uncommitted on the branch), suite,
  PHPStan and cs re-verified.
- Composer scripts on that branch: `composer build` = `phn build src tests`,
  `composer build:check` = `phn build --check src tests`. They call `phn` from `PATH`.
- Verify: `composer build:check`, then its phpunit (25 tests), `composer phpstan` (level 10) and the
  php-cs-fixer check, which skips files carrying `@generated by phaenon`.
- `../jetbrains/src/test/testData/reflector/*.phn` are copies of these sources.

## `tequila/object-mapper` — M2, M3

- Repo `~/labs/tequila/object-mapper`. `main` is plain PHP (23 files in `src/`); branch
  **`phaenon-dogfood`** (local only, 2026-10-28) holds the migrated tree: 51 `.phn` files
  (`src/` + `tests/`) with generated `.php` beside them, `phn migrate` having lifted the generics.
- M2: `phn check src` reported 0 findings on those 23 files — the same as PHPStan level 10.
- M3: `phn check src` = 0 findings with real generics (re-verified 2026-10-29 after
  `class-string` → `class`, uncommitted on the branch; the generated `.php` did not change); `composer test` (19 tests), `composer phpstan`
  (level 10) and the cs check (skips `@generated by phaenon`) pass. `tests/` has 16 findings PHPStan
  never saw ([[open-items]]), so tests are built with `phn build --no-types tests`.
- Composer scripts `build` / `build:check` as in reflector.
- Its `tools/phpstan` is the PHPStan used for parity runs ([[testing]]).
